D — Capture queue (rotation-first, draft-and-promote)

The time-sensitive act is getting the record into a bin, not into the card catalog. Capture takes seconds with zero catalog knowledge; cataloging is a second pass over the queue via the import screen — which already matches or creates the artist and files the release in one action. The structural change: Import unlocks for active rows.

▶ Live demo — the capture form live-matches the artist name (Juana Molina is seeded; try misspelling it). Capture a record, watch it join the queue, then click Import on it: a matched artist auto-selects; an unknown one gets the inline new-artist form. Kill/Unkill work too.

Annotations

  1. 1Heavy is already the default (DEFAULT_BIN in RotationReleaseInsert) — right for a new-record workflow where most arrivals open heavy or medium.
  2. 2The capture form is untouched — this strategy is a policy change plus one unlock. Its virtue is rush-proofness: nothing about cataloging blocks airplay.
  3. 3"Awaiting Cataloging" is the getUncataloguedRotation facet. The visible count is deliberate: this strategy fails quietly if nobody owns the second pass, so the backlog number needs to be in someone's face.
  4. 4The change: today RotationReleaseList renders Import only for rows that are killed and unlinked — the fast path and the catalog can only meet after the record leaves rotation. Unlocking active rows is a one-condition change in the row-action logic. The killed Csillagrablók row shows today's only-after-death behavior.
  5. 5The import panel mirrors RotationImportScreen, already the best filing UX in the app: library-wide artist match with auto-select and an escape hatch, inline new-artist form with suggestCallLetters and computed next code, one Catalog & Link action. Strategy D is "make the good screen reachable in time to matter."

Tradeoffs to weigh before choosing this as primary

  1. !The library lags rotation: until import, the row has no album_id, so catalog search won't find it and album-linked surfaces can't show it.
  2. !Every record is touched twice, and free-text typos at capture become the import screen's matching problem later (try capturing "Juana Nolina" — the auto-match misses and you're in the new-artist form for an artist that exists).
  3. !Queue ownership is a people problem, not a UI one — without a norm ("imports happen at the weekly meeting"), Awaiting Cataloging becomes a debt counter.
