E — Search-miss entry ("no results → file it")

The search is the entry point: the zero-results state offers to file the release, seeded from the structured query rows — an exact field mapping, no fuzzy parsing. Directors get dedup for free because searching first is exactly the check fast entry skips.

▶ Live demo — the seeded query is a partial match (artist exists, release doesn't). Try album "Hijos del Sol" for a full hit, change the artist to something unknown for a full miss, or clear the album to browse the artist. The CTA really hops to the filing bench pre-seeded (open from disk).

Annotations

  1. 1The query rows already carry {field, value} (catalogSlice's CatalogSearchRow), so "artist" and "album" map to bench fields exactly — the structure was already paid for. This is what makes E cheap here where it's fuzzy elsewhere.
  2. 2The partial-match state is the real dedup win: "artist exists, release doesn't" vs. "neither exists" tells the MD which half of the filing they're doing — and the CTA pre-selects the matched artist in the bench, skipping the create-artist branch entirely.
  3. 3Entry point, not a flow: the CTA routes to mockup A's bench with ?artist=&album= — in this demo that's a real link, and the bench really reads it. E only pays off once A (or B) exists behind it.
  4. 4Gate the CTA on the MD role (the RequireMD wrapper AddReleasePanel already uses); DJs keep the plain empty state so search stays a read-only surface for them.
