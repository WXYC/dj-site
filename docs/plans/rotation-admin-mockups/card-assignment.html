Card assignment panel

The tool for the one-time re-carding pass (B3 / B4 in the rotation age epic). When Rotation Admin launched, the backfill put every active record on card 1 of its bin. The only way to move them today is the per-row select on the Rotation list, one record at a time. This panel turns the pass into a walk along the shelf: open a card, tick what is physically on it, save, open the next.

▶ Live demo — open Assign records on Heavy 3, switch the filter to Still on Heavy 1, tick a few, and Save & open Heavy 4. Tick the box to make one move fail and see the retry ledger.

Annotations

n design note    n depends on backend work — everything else is dj-site only

  1. 1Card-centric because the pass is a walk along the shelf. An MD stands at one physical card, looks at what is on it, and makes the database agree. Entering from the card, rather than from each record, turns a few hundred per-row selects into one pass per card. The existing rename, add and delete controls on the tab are unchanged.
  2. 2Only this bin's active records appear. Moving a record between bins is add-then-kill (addThenRetire.ts), not a card change, so another bin's records never show up here. Killed records are not on any physical card. The list reads GET /library/rotation?status=active, never status=all: the Cards tab should not pay for the full rotation history.
  3. 3Records already on this card are ticked and locked. Unticking would leave a record with nowhere to go. A record comes off a card only by being ticked onto the card it actually sits on, so every save is a set of moves onto the open card, which fits a card-by-card walk. The row's hover text says so.
  4. 4"Still on Heavy 1" narrows to the backfill pile. On 2026-09-15 the migration put every active record on card 1 of its bin, so most of the pass pulls from there. The filter is named for the card, not "unassigned", because card 1 is also a real card, and plenty of records legitimately belong on it.
  5. 5Every record shows where it is now, and a tick previews the move (Heavy 1 → Heavy 3). Nothing is written until Save.
  6. 6One batch, one refetch. Save sends the existing PATCH /library/rotation/:id {card_id} once per moved record; there is no new endpoint. It goes through a single moveRotationRowsToCard mutation, not updateRotationRow in a loop. updateRotationRow refetches the cards list and the rotation list after every call, which would shuffle the checkboxes mid-save. The batch refetches both once, when it settles; watch the counters above. It also moves each saved record in the cached Rotation list, so that tab is correct without another read.
  7. 7Not transactional, so the outcome is per record. Each move either lands or it doesn't. Moved records lock onto this card; a failed one stays ticked, marked, with Retry resending only the failures. A single "something went wrong" would leave the MD unable to tell what is on the card now.
  8. 8Save & open the next card is the walk. It only advances when every move landed; with any failure it stays put and shows the retry ledger.
  9. 9Every move stamps two cards, the one the record left and this one. That comes from Backend-Service's rotation_cards.last_changed_at trigger (B2), which is why the pass (B4) should run only after B2 is confirmed live: before it, the reorganization leaves no timestamps. This page does not display the stamp; showing it is B5.
  10. 10Duplicate active rows are invisible here. The active rotation read collapses several active rows for the same release in one bin into one (DISTINCT ON, a leftover of tubafrenzy re-adds). A hidden duplicate could never be re-carded, and it would keep stamping card 1. B4's first step finds them with a read-only query, and an MD kills them on the Rotation list, which shows every row.
  11. 11Named the way MDs say it: "Heavy 3", not "card 3". Asked about "rotation cards", Sam replied "Is that like 'Heavy 9'?" The tab keeps its name, but the panel, its buttons and its summaries lead with bin and number.
  12. 12Mostly a one-time tool, so it stays plain. Sam: "we always trade things out piece wise never all at once so far." Day-to-day swaps are one record at a time, and the bench's card picker and the Rotation list's per-row select already cover them. This panel pays for itself on the pass and any future reshuffle, which is why it is checkboxes and a save button, not drag-and-drop.
