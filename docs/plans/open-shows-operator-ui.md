# Open Shows operator UI

## Why

Backend-Service shipped the abandoned-show operator endpoints in BS#2235 — `GET /flowsheet/open-shows` and `POST /flowsheet/shows/:id/force-end`, both gated `flowsheet: ['manage']` (musicDirector + stationManager) — as the replacement for tubafrenzy's `EndShowServlet` / "Resume a Show" path, which retired 2026-09-07. dj-site references neither, so the capability has no product surface: closing the stuck show 1951317 on 2026-09-08 took a hand-built shell script, a JWT minted from a devtools console with a 15-minute fuse, and four failed attempts (missing `?force=true`, clipboard newline → nginx 400, expired token) before it landed. BS#2388 records the incident; this page is the standing fix.

The go-live takeover flag (`FLOWSHEET_TAKEOVER_ENABLED`, now ON in production) covers the common case — the next DJ arriving at a stuck show can end it from the handoff prompt. What it cannot cover: nobody is arriving (overnight, summer), the operator isn't physically at the station, and the ~2,813-row legacy backlog. Those need a list-and-close surface.

## Backend contract (read from Backend-Service source, verified live 2026-09-08)

`GET /flowsheet/open-shows?window_hours=&limit=` → `{ shows: OpenShow[], total_in_window, older_open_show_count }`. Oldest first. `OpenShow`: `{ id, primary_dj_id, dj_name, show_name, start_time, legacy_show_id, entry_count, is_current, likely_abandoned }`. Defaults `window_hours=168` (7 days), max `262_800` (30 years — sized to reach the 2006 tail); `limit` default 100, max 500. `shows.length < total_in_window` is the only truncation signal; `older_open_show_count` counts open shows older than the window and is a count, never a list.

`POST /flowsheet/shows/:id/force-end` → the finalized `Show`. Stamps `end_time` from the show's last logged entry (`resolveForceEndInstant`), never `now()`. Refusals: **409** `"Conflict: this is the current on-air show. Re-send with ?force=true to end it anyway."` when the target is `max(shows.id)` without `?force=true` (an abandoned show IS current until something closes it, so the stuck-show case always trips this); **400** `"show is already ended"` (lost a race — benign); **404** unknown id. Optional body `ended_at` adjusts the instant upward only — not surfaced in this UI (the derived instant is the honest default; an override field invites typo'd timestamps into the public archive).

Both routes 403 below musicDirector; the server is the authority and the UI gate is an affordance-hider only.

## Decisions

- **Modern-only, at `app/dashboard/@modern/admin/shows`.** Every admin surface (roster, catalog admin) is modern-only; classic URLs fall through to `@classic/default.tsx`'s `ExperienceGap`, which was built precisely so modern-only routes need no classic stub. No classic work.
- **Server-gated at `Authorization.MD`**, exactly like `admin/catalog/page.tsx` (`requireAuth()` + `requireRole(session, Authorization.MD)`), because the backend grant is `flowsheet: manage` = MD + SM. Roster's SM gate is the wrong precedent — that matches its own backend grant, not this one.
- **Endpoints live in `lib/features/flowsheet/api.ts`**, not a new feature dir. The domain is the flowsheet, the base query already carries the bearer token, and `forceEndShow` must invalidate this API's own tags (`WhoIsLive`, `NowPlaying`, `Flowsheet`) — cross-API invalidation would need `invalidateTags` dispatches across slices for no structural gain. New tag `"OpenShows"`.
- **`getOpenShows` opts out of the soft-fail** with `extraOptions: { surfaceNonJsonAsError: true }`. The architecture doc's rule: a failed read must never render as the empty state. "No open shows" while the backend is down would tell an operator the cleanup is done. The two librarian cross-reference views are the stated precedent.
- **Leftbar link "Open Shows"** in the existing admin section (visible `> Authorization.DJ`), inserted between "Catalog Admin" and the disabled "Station Schedule", with the `Sensors` icon (`@mui/icons-material` broadcast-waves glyph; `LeftbarLink` requires an icon child). Not `disabled`-gated below MD: the whole admin block is already hidden at DJ and below, and both remaining tiers (MD, SM) hold `flowsheet: manage` — a disabled state would have no audience, unlike roster's SM floor which excludes MD.
- **`?force=true` is driven by the row's own `is_current`, snapshotted at click time into the confirm dialog.** The dialog for a current show says what the action does — sign the on-air DJ off — in danger color; the dialog for a non-current show is the ordinary variant. The server 409 remains the backstop for the snapshot going stale (show became current between render and click): the dialog re-opens in its danger variant with client-owned copy ("This is now the on-air show — ending it signs the current DJ off the air"), and never auto-retries with force — auto-escalating on a 409 would be the client overriding the exact consent gate the server put up. The raw server message ("Re-send with ?force=true…") is an API instruction and never reaches the operator; the client can recompute everything it conveys, so per the architecture doc's delete-refusal convention the screen owns the words.
- **400 "already ended" is treated as success with an info toast** ("Show was already closed") + list refetch: the operator's goal state is reached; a red error for it would read as failure and invite a retry loop.
- **`forceEndShow` wraps its error via `transformErrorResponse`** (`{ forceEndShowError: response }`), the `deleteAlbum` pattern (`lib/features/catalog/api.ts:240-248`): the shared `rtkQueryErrorLogger` toasts `data.message` on every rejected mutation, so without the wrap the benign 400 would render a red "show is already ended" over the info toast, and the 409 would double-toast. The wrap silences the *toast* only — `safeCaptureException` runs unconditionally before the message check, so the benign 400 still files a generic Sentry event. Accepted explicitly: that 400 fires only when two operators race to close the same show, rare enough that plumbing a deliberate status-carrying report would build reporting nobody triages.
- **One owner for the force-end outcome: `lib/features/flowsheet/force-end-outcome.ts`** (kebab-case beside `go-live-handoff.ts`, which owns the identical job for the go-live 409 — interpretation, copy, testids in one module). It owns the unwrap of `{ forceEndShowError }` back to the inner `FetchBaseQueryError` (the `releaseDeleteOutcome.ts:122-127` shape), the outcome union (`ended` / `already_ended` / `now_on_air` (409) / `refused` (403/404/other 400s) / `indeterminate` (5xx, network, or an unwrapped rejection that never reached the transform)), the dialog's client-owned copy, and the testids. Both `invalidatesTags` and `ForceEndDialog` consume it — the classification is never derived twice. Critically, `invalidatesTags` must unwrap before reading `status`: the transform runs first, so a status-keyed mapping against the raw error reads `undefined` on every refusal and would fall into the invalidate-everything branch on exactly the 403/404/409 cases the function form exists to protect. An unwrapped rejection is `indeterminate`, never `refused`.
- **`invalidatesTags` uses the error-aware function form**, because RTK invalidates on rejection too — the array form would refetch the live entries feed, now-playing and who-is-live on a 409 that changed nothing upstream (`deleteAlbum`'s comment at `catalog/api.ts:250-266` is the precedent). Mapping (computed from the outcome module, never inline): `ended` → `["OpenShows", "WhoIsLive", "NowPlaying", "Flowsheet"]` (closing the current show changes all four); `already_ended` → `["OpenShows"]` (delivers the list refetch that decision needs, touches nothing live); `now_on_air` / `refused` → `[]`; `indeterminate` → the full set, because the close may have committed on a response the client never saw, and skipping invalidation there leaves every surface asserting a show that is gone.
- **Windowing UI is one control, not a form.** Default request is the backend default (168h). When `older_open_show_count > 0`, render "N older open shows — show all" which re-queries with `window_hours=262800, limit=500`. When `shows.length < total_in_window`, render the truncation notice ("showing X of Y in this window"). No free-text hour input — the two canned windows cover both real tasks (recent cleanup; full backlog audit), and the backend caps are not knowledge an operator should need.
- **`OpenShowsTable` owns its scroll container** (`overflow: "auto"` box, roster's `RosterTable.tsx:139` placement): modern's `Main` is `height: 100dvh; overflow: hidden`, so a page that owns no scroll box has a 500-row "show all" table clipped below the fold, not scrolled to.
- **Query params go through `fetchBaseQuery`'s `params:` object**, matching every parameterised flowsheet query (`api.ts:453/:462/:471`) — it also drops `undefined` for free, which is exactly what "omit to get the backend default" needs.
- **Times render via the browser locale** like the rest of the dashboard, with the raw ISO on `title` hover. Column set: Started · DJ · Show name · Entries · status badges (ON AIR for `is_current`, "likely abandoned" for `likely_abandoned`) · End action. `dj_name` may be null (legacy shows) → render "—".

## Tests (TDD order)

1. `tests/unit/lib/features/flowsheet/force-end-outcome.test.ts` — the outcome union from raw fixtures: wrapped 400-already-ended / 403 / 404 / 409 / 5xx / network error / **unwrapped rejection** (must classify `indeterminate`, not `refused`); copy and testid pinning per the `go-live-handoff.test.ts` convention.
2. `tests/unit/lib/features/flowsheet/openShows.test.ts` — API harness: `getOpenShows` request shape via `params:` (default vs widened window), soft-fail opt-out behavior (HTML body → error, not `{data:null}`); `forceEndShow` URL + `?force=true` presence/absence keyed to the arg; tag wiring: success refetches an active `getOpenShows` subscription, a 409 refusal does NOT refetch an active `getInfiniteEntries` subscription (the unwrap-before-status bug would).
3. `tests/integration/components/modern/admin/shows/OpenShowsTable.test.tsx` — `renderWithProviders` + MSW: renders rows oldest-first with badges; truncation notice at `shows.length < total_in_window`; "show all" re-queries with the max window; empty vs error states are distinct.
4. `tests/integration/components/modern/admin/shows/ForceEndDialog.test.tsx` — danger copy + `force=true` only for `is_current`; 409 → dialog re-opens in danger variant with client-owned copy, no auto-retry-with-force, no raw server text; 400 already-ended → info toast, no red toast (proves the `transformErrorResponse` wrap silences the middleware); success → row leaves the list.
5. `tests/integration/app/dashboard/@modern/admin/shows/page.test.tsx` — the server gate, modelled on the catalog admin page's suite (asserting on the `NEXT_REDIRECT` marker): below MD redirects, MD and SM render. The Leftbar link is affordance-hiding; this test covers the thing that actually keeps a DJ out.
6. Leftbar test extension in its existing suite: link present for MD/SM, absent for DJ.

Fixture DJ/show names follow the existing flowsheet test conventions (`tests/helpers` factories; WXYC catalog data per `docs/test-fixtures.md`).
